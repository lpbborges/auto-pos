# Sale Date Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Allow users to specify a custom sale date (defaults to today) when completing a sale, so past sales can be backdated.

**Architecture:** Add a `sold_at DATE` column to the `sales` table. The checkout dialog always shows a date picker defaulting to today. The server reads and validates the date, stores it in `sold_at`. The sales history page displays and filters by `sold_at` instead of `created_at`.

**Tech Stack:** SvelteKit, Supabase (PostgreSQL), Svelte 5, TypeScript, Vitest

**Step 2: Update the date filters to use `sold_at`**

Change all three `filter` blocks to filter on `sold_at` instead of `created_at`. The `sold_at` column is a DATE, so compare against a date string (not ISO timestamp).

Replace the entire `if (filter === 'today') { ... } else if (filter === 'week') { ... } else if (filter === 'month') { ... }` block with:

```ts
if (filter === 'today') {
  query = query.eq('sold_at', now.toISOString().split('T')[0])
} else if (filter === 'week') {
  const sevenDaysAgo = new Date(now.getTime() - 7 * 24 * 60 * 60 * 1000)
  query = query.gte('sold_at', sevenDaysAgo.toISOString().split('T')[0])
} else if (filter === 'month') {
  const startOfMonth = new Date(now.getFullYear(), now.getMonth(), 1)
  query = query.gte('sold_at', startOfMonth.toISOString().split('T')[0])
}
```
